Konfiguracja Redis jako backendu cache:




1. Instalacja i uruchomienie Docker Desktop

Na komputerze został zainstalowany Docker Desktop.
Ponieważ Docker wymagał WSL, zainstalowano Windows Subsystem for Linux:

wsl --install

Po instalacji WSL oraz Ubuntu wykonano ponowne uruchomienie komputera.

2. Sprawdzenie działania Dockera

docker --version

Polecenie potwierdziło poprawną instalację Docker Desktop.

Następnie sprawdzono działające kontenery:

docker ps

Początkowo lista była pusta, ponieważ żaden kontener nie był jeszcze uruchomiony.

docker run --name lesson27-redis -p 6379:6379 -d redis

6. Przygotowanie projektu Django do współpracy z Redis

Przejście w PowerShellu do katalogu projektu lesson27:

cd D:\PythonPro-Course\homework\lesson27

Polecenie cd (change directory) zmienia bieżący katalog terminala.
W tym przypadku przechodzimy do głównego katalogu projektu Django,
w którym znajduje się plik manage.py oraz środowisko wirtualne .venv.


7. Aktywacja środowiska wirtualnego

.\.venv\Scripts\Activate.ps1

Polecenie aktywuje środowisko wirtualne .venv utworzone dla projektu.
Po jego wykonaniu przed ścieżką w terminalu pojawiło się:

(.venv)

Oznacza to, że polecenia python i pip korzystają teraz z interpreterów
i bibliotek zainstalowanych lokalnie dla projektu lesson27, a nie
z globalnego środowiska Python w systemie Windows.


8. Instalacja biblioteki django-redis

pip install django-redis

Biblioteka django-redis umożliwia wykorzystanie serwera Redis jako
backendu mechanizmu cache w aplikacji Django.

Polecenie zwróciło:

Requirement already satisfied: django-redis

Oznacza to, że biblioteka django-redis była już wcześniej zainstalowana
w środowisku .venv i nie było potrzeby instalowania jej ponownie.

W środowisku dostępne są również wymagane zależności, między innymi:

Django 6.0.7
django-redis 7.0.0
redis 8.1.0

Pakiet redis jest biblioteką Pythona umożliwiającą komunikację aplikacji
z działającym serwerem Redis.

9. zmiana w CACHES w config/settings.py a następnie sprawdzenie poprawności za pomocą poleceni python manage.py check
oraz test zapisu i odczytu w Redis.


CACHES = {
    "default": {
        "BACKEND": "django_redis.cache.RedisCache",
        "LOCATION": "redis://127.0.0.1:6379/1",
        "OPTIONS": {
            "CLIENT_CLASS": "django_redis.client.DefaultClient",
        },
    }
}

"BACKEND": "django_redis.cache.RedisCache", #linia ta oznacza, że Django cache ma korzystać z Redis przez django-redis

 "LOCATION": "redis://127.0.0.1:6379/1", 

127.0.0.1 - adres działania Redisa na komputerze
6379 — domyślny port Redis,
/1 — baza Redis nr 1.

"CLIENT_CLASS": "django_redis.client.DefaultClient", # ustawia standardowego klienta django-redis

po zapisaniu settings.py uruchomiono python manage.py check


(.venv) PS D:\PythonPro-Course\homework\lesson27> python manage.py check      
System check identified no issues (0 silenced).
